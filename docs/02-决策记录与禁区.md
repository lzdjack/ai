> 这份文档记录了定稿过程中**被用户否掉的方向和原因**。以后用 AI 做这个产品的任何界面，先看完这页。
> 这里列的做法都已经被否掉，不要再拿出来当新方案。

## 一、风格方向

| 被否掉的 | 用户原话 / 原因 | 正确做法 |
|---|---|---|
| 后台管理风（侧边菜单加表格加卡片墙） | 「不好看，不要做的跟后端管理一样」 | 苹果系毛玻璃，像原生应用 |
| 可点击的产品原型、线框图 | 「我要的不是产品原型图，我要的是 UI 设计图」 | 高保真静态设计图（PNG） |
| 「炫酷」做成霓虹、赛博、粗野主义、杂志风 | 「你现在做的太抽象了」，要好看、功能方便 | 炫酷 = 精致的苹果质感，不是怪风格 |
| 午夜蓝、Tita 蓝、深海三套主题 | 不好看 | 苹果毛玻璃（亮加暗） |
| 底部大胆的浮动操作区、扇形菜单、岛屿 | 「太夸张了」 | 常规结构：左菜单、三栏面板、对话底部输入框 |

## 四、工作方式（同样重要）

1. **先出一张精细图，确认后再铺开。** 用户原话：「不要多出，出个精细的设计图，我满意了你再做全部」。
2. **只改用户指出的位置。** 用户截图圈出一块，就只改那一块，其余保持不变。
3. **要备选时，做成一张对比图**，并排放 3 到 4 种，标上编号和一句话说明，亮色和暗色都要。不要散着出一堆单独的文件。
4. 每版都出亮色和暗色。
5. 本地 HTML 渲染成 PNG，**不上传网络**。
6. 交付前自己先看一遍渲染结果：文字有没有换行、有没有元素重叠、有没有被遮挡、有没有冒出旧的图标，有就先修好再给用户。
7. 不要自己改用户已经定下的东西。用户没提的部分沿用定稿。
8. **所有给人看的文档和设计统一收口进唯一的 `index.html`**（2026-11-23 用户确认：「以后都放到一个 html 文档里面，这样就一个就行了，不需要再到处乱找了，他是一个集合」）。产品需求、修复流转方案、链路流转、设计主题、PC / 移动端设计图、技术设计方案（`06-技术设计方案.md`）、决策与后续全部通过 `scripts/build-index.py` 汇入根目录唯一的 `index.html`，不再另开分散的 HTML 文档；每次更新文档或设计图后重新运行构建脚本。
