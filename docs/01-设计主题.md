# 云匠（CLOUDCRAFT）· UI 设计主题（定稿）

> 定稿日期：2026-11-20 · 适用：PC + 移动端 · 亮色 + 暗色
> 定稿图：`reference/images/PC-主界面-亮色.png`、`PC-主界面-暗色.png`、`移动端-亮色.png`、`移动端-暗色.png`
> 所有颜色、尺寸的源值：`tokens/theme.css`；可运行的源文件：`reference/src/`

---

## 1. 一句话风格

**苹果系 · 毛玻璃 · 对话流。** 看起来像一个 macOS / iOS 原生应用，不像后台管理系统。

- 背景是柔和的多色渐变「壁纸」，所有面板都是半透明毛玻璃浮在上面。
- 主要工作区是「对话流」：每张工单就是一段和 Bot 的对话，交付、审核、打回都在对话里发生。
- 颜色只用苹果系统色；彩色只出现在菜单图标、状态和主按钮上，其余都是中性色。
- 高保真、具体、好用。不抽象、不炫技、不做原型线框。

### 2.2 毛玻璃

```css

/* 亮色 glass .52 白 / glass-2 .78 白；暗色 glass rgba(36,38,50,.52) / glass-2 rgba(58,60,74,.66) */
```

### 2.6 滚动条规范（全局硬规，2026-11-24 定稿）

**全站所有可滚容器统一采用「零占位悬浮滚动条」**，Mac / Windows / iOS / Android 体验完全一致，绝不允许出现挤压对齐的经典粗滚动条或「框中框」外边框：

- **0px 布局占位**：滚动条悬浮在容器内侧边缘（`right: 2px`），**绝对不占容器宽度**，无论内容是否超出高度，卡片左右边缘与中缝永远 100% 像素齐平、零抖动。
- **默认隐藏 · 移入/滚动显示**：静置态 `opacity: 0` 完全隐藏；鼠标移入容器或滚动时 `180ms` 平滑淡入（宽 `5px` 圆角胶囊，`--sb-thumb` 亮色 `rgba(29,29,31,.20)` / 暗色 `rgba(245,245,247,.24)`），移出或停止滚动 `800ms` 后自动淡出隐藏。
- **跨平台实现（PC Electron / React）**：因 Windows Chromium 已废弃 `overflow: overlay`，原生 `overflow: auto` 会挤出 15px 灰条——**禁止裸用系统滚动条**，统一封装 `<ScrollArea>`（基于 Radix UI ScrollArea / OverlayScrollbars，隐藏原生条 + 绝对定位悬浮 thumb，token 见 `tokens/theme.css`）；移动端 Flutter 默认 `CupertinoScrollbar` 原生即 0 占位悬浮。
- **静态设计图规范**：同「静态图不画 tooltip」，默认静置态不画常驻滚动条；需要暗示下方可滚时，对列表底部施加纯透明羽化遮罩（`mask-image: linear-gradient(180deg, #000 72%, transparent 100%)`），让下一行卡片自然淡入毛玻璃背景。

### 3.1 顶栏

- **左**：44px logo（蓝紫渐变圆角方块，白色代码括号加对勾，右上一颗小星光）加两行标题：「**云匠**」（`Hiragino Sans GB` / `PingFang SC`，17.5 / 600，字距 1.4px）和「**CLOUDCRAFT**」（`Optima` / `Avenir Next`，11 / 700，大写，字距 1.8px，亮色蓝紫渐变 `#2563EB → #6D28D9`，暗色 `#7DD3FC → #C4B5FD`）。logo 和下方菜单图标竖直居中对齐；**空间切换收在右上角头像菜单里，品牌区不放空间胶囊**：可用工作空间 `>= 2` 时头像右下角加 17px 当前空间角标（个人空间为小人图标、团队空间为团队首字），点头像弹出菜单：账号信息 → 工作空间列表（当前项打勾，其他空间带待办数）→ 原地升级为团队（就地展开填写）→ 输入邀请口令 → 我的账号 / 退出登录；单空间用户不出角标和空间分组（图 `PC-头像菜单-切换空间与升级团队`）。
- **中**：毛玻璃搜索框 440 × 36，圆角 11，右侧 `⌘F`。
- **右**：状态胶囊依次为「3 个 Bot 在线」、按已接入 `ticket_source` 连接器动态呈现的健康胶囊（正常青绿、采集失败/令牌过期橙红，最多 2 个微胶囊超限折叠）、**`34px` 毛玻璃通知铃铛微按钮**（点击弹出 `400px` 站内通知抽屉 `z:60`，不占 Dock 与插件胶囊槽位）、然后是 34px 头像；真机端 macOS 为原生交通灯留 76px 左安全距，Windows 为右侧 `TitleBarOverlay` 预留 138px 避让区。
- 不要在设计图上画 macOS 红黄绿三个圆点。

### 3.2 左侧 Dock 菜单（核心辨识点）

- 竖向毛玻璃栏，**只放图标、不放文字**，和 macOS Dock 一样。
- 图标是 44px 彩色圆角方块，带顶部高光、内阴影和投影，间距 10。
- 从上到下：

| 图标 | 底色 | 图案 |
|---|---|---|
| AI 助手（全局） | 深色 `#141530` 加彩色光晕 | 白色星光 |
| —— 分隔线 —— | | |
| 对话 | 白色（暗色为深灰） | 蓝色双气泡 |
| 发布 | 橙色渐变 | 白色包裹 |
| 紧急回滚 | 红色渐变 | 白色倒转时钟 |
| Skills | 紫色渐变 | 白色三层叠片 |
| 插件市场（位于设置上方） | 绿青蓝渐变（`#34D399 → #0284C7`） | 白色四宫格方块 + 右下星光 |
| 设置（固定在最底部） | 灰色渐变 | 银色齿轮 |

- **选中态 = 放大 + 悬浮**：选中的图标放大到 1.16 倍，投影加深加散；其余图标缩到 0.94。不加小圆点、托盘、描边环、光条或悬停提示框。
- **插件图标上限防爆（2026-11-24 定稿）**：多数插件（连接器、审批卡点、CLI 适配器）不占 Dock；仅一级工作区模块允许声明 `dock.items`。核心固定图标之外，**外挂插件图标最多直出 4 个**，超出自动聚合进一个毛玻璃「**更多插件（`+N`）**」文件夹图标（点击弹网格，支持拖动把常用的固定到外层）。
- 数字角标：红色 18px 圆，右上角，外圈有 2px 毛玻璃色描边。

### 3.3 工单列表

- 头部：「工单」18/700，后面跟总数「8」(text-3) 与蓝色 24px 圆角 `+` 按钮（点开「手动新建工单」对话框）；右侧分段控件「我的 / 全部」。
- 分组按「等你做什么」排序：**需要处理（红）→ 等你决定（蓝：待我审核 + 轮到你操作的发布/MR/复测）→ Bot 在问你（橙）→ Bot 修复中（青）→ 排队中（灰）→ 发布与复测中（非你当前卡点的在途交付）→ 待原平台确认（绿）→ 已完成（仅「全部」底部）**；空分组自动折叠隐藏（常规下即呈现经典 5 组，且确保任意状态零漏单、单单仅落 1 组）。分组标题 11.5/600 text-3，数字放在灰色小胶囊里；「我的」动态涵盖修复人、指派测试人、MR 审核人、指定发布人与在途发布发起人。
- Dock 红点双端同源互斥计数（操作完成才消）：「对话」统计待你处理的独立工单，「发布」统计待你处理的独立发布任务/大包；行内 8px 未读点随任一端打开详情实时同步消除。
- **行结构**：
  - 左：**提单人头像**，34px 圆形，柔和渐变，白色两字姓名。系统单显示「OKR」，用灰色。
  - 头像右下角是 12px 状态点，颜色按下面的状态映射，外圈有 2.5px 描边。
  - 第一行：标题 13.5/600，右侧是时间（11 text-3）或未读点（8px）。
  - 第二行：来源标签「Tita」或「Jira」（16px 高的小胶囊），后接状态说明（12 text-3）。Bot 提问用橙色，需要处理用红色。
  - 修复中的单在底部加一条 3px 青色进度条。
  - 行与行之间是细分隔线，左边缩进到头像之后。
- **选中行**：蓝色渐变实底（`#3B8BFF → #1F6FFF`），白字，圆角 14，带蓝色投影。选中行里的状态点外圈改成白色。
- 状态映射：待审核 = blue · 受阻 / 在问 = orange · 修复中 = teal · 已通过 = green · 需要处理 = red。

### 3.4 工单对话（主区）

- **头部**：TITA/JIRA 来源方块（40px），标题 22/700，下面一行是元信息（`TK-20871 · P1 · 模块 · 修复人 · 执行 Bot`），右侧是「待我审核 · 第 2 轮」蓝色胶囊。
- **分段控件**：核心 4 项「对话 / 代码改动 3 / 证据 4 / 执行日志」+ 已启用的扩展模块标签（默认安装发布插件时呈现第 5 项「发布」；通过 `ticket.tabs` 最多直出 2 个常用插件标签，超出自动收进 `更多 ▾` 下拉），右侧是「打开 Tita 原单 ↗」链接（手动新建工单隐藏原单链接）。
- **对话流**：
  - 每一轮之间用居中的细线分隔，写明轮次和时间，例如「第 1 轮 · 昨天 22:40 交付 · 你打回了」。
  - 你说的话是右侧蓝色渐变气泡，圆角 `18 18 6 18`。
  - Bot 的步骤是一行毛玻璃条：复现 ✓ 定位 ✓ 改代码 ✓ 浏览器验证 ✓，右侧写「用时 42 分钟 · 展开过程 ›」。
  - **交付卡**（glass-2，圆角 18），从上到下：标题「第 N 轮交付：已修复，等你确认」、根因、回应上轮（✓ 已处理 + 看相对上轮的改动 ›）、修复前后两张截图（修复后加 2px 绿色描边，标注「已查阅 / 未查阅」）、验证清单（未测项用橙色 !）、改动文件（+38 −12 · MR）和用到的 Skills 小胶囊。
- **审核行**：左边写「审核对象 a3f9c21」；右边是「打回并说明原因」（浅红底红字）和「审核通过 a3f9c21」（蓝色主按钮）。
- **本单 AI 输入框**：放在对话最底部。左侧是紫色标签「✦ 本单 AI · TK-20871」，占位文字「问这张单，或让 Bot 再做点什么…」，右侧依次是回形针和 38px 蓝色发送按钮。

### 3.5 右侧信息栏

自上而下三张卡片：

- **经过**：时间线，绿 / 红 / 蓝三色节点。
- **环境版本**：测试环境、正式环境、测试人。
- **各项进度**：代码审核（显示「等你」）、发布·复测、原平台确认。

最底部是「我已在原单确认」按钮和外链按钮。

## 4. 两个 AI 的区分（不能冲突）

| | 全局 AI（AI 助手） | 本单 AI |
|---|---|---|
| 入口 | 左侧菜单第一个图标；移动端是 Tab 栏第一个图标 | 每张工单对话的最底部 |
| 形态 | **独立页面**（不是顶栏输入框） | 对话输入框 |
| 标识 | 彩色光球和三色渐变（蓝 → 紫 → 粉） | 紫色标签，永远带工单号 |
| 管什么 | 跨工单、发布、收单情况；搜索 | 只管这张单：问改动原因、补资料、让 Bot 复测 |

AI 助手页的结构：顶部是光球加问候语（「下午好，林某」和今日概况），下面是常用问题胶囊，回答里直接列出相关工单行，每行带「去审核」按钮。底部输入框带三色渐变描边。

## 5. 移动端（390 × 844）

- 和 PC 用同一套壁纸、毛玻璃、颜色、头像列表和菜单图标。
- **底部 Tab 栏**：悬浮毛玻璃条，左右 14、底部 24，高 70，圆角 26。保持 **≤ 5 个**核心彩色图标入口（默认：AI、工单对话、发布主流程、可配扩展槽如回滚、Skills），不带文字；未启用回滚扩展时保留 4 图标并把额外插件收口在「设置 → 插件市场」。选中的图标同样是放大加悬浮（1.14 倍，上移 3px）。设置放在头像里。
- **首页（工单列表）**：
  - 小字日期加大标题「工单」，右上角是头像。
  - 可用工作空间 `>= 2` 时，点头像推入二级页「账号与空间」（左上「‹ 工单」返回、隐藏 Tab 栏）：账号卡片 → 工作空间列表（当前项打勾，点一下就切换）→ 输入邀请口令 → 退出登录。不在首页弹浮层，也不在首页顶部放空间胶囊（图 `移动端-剪贴板识别邀请` 第 3 屏）。
  - 下面依次是状态胶囊、搜索框（40px，圆角 12）、三张数字卡片（等你决定 / Bot 在问你 / 修复中，当前项用 glass-2 托起）。
  - 列表是 iOS 的分组卡片样式（毛玻璃，圆角 18），头像 40px。
- **工单对话**：
  - 顶部导航「‹ 工单 / TK-xxxx / …」，下面是标题、标签和四段分段控件。
  - 对话内容和 PC 一致，截图缩小后左右并排。
  - **底部固定操作区**（毛玻璃，圆角 26）：上一行是「打回」和「审核通过」两个按钮，宽度比 1 : 1.6，高 44，圆角 14；下一行是本单 AI 输入框。
- **AI 助手**：光球 68px，常用问题胶囊居中换行，渐变描边输入框放在 Tab 栏上方。

### 5.1 支持的系统（2026-11-21 用户确认）

首批支持 Mac、Windows、iOS、Android。设计图只画一套（PC 按 Mac、手机按 iPhone 画），风格、布局、组件不分系统；落地时只做系统本身的差异：

- **Windows**：不画 macOS 红黄绿圆点（Mac 上也不画），窗口按钮用系统自带的放在右上；快捷键 ⌘ 换成 Ctrl；字体用微软雅黑 / Segoe UI 兜底，字号不变。
- **Android**：状态栏、底部手势条用系统的；返回靠系统返回键 / 手势，页面左上「‹ 上一页」照样保留；底部 Tab 栏、毛玻璃、圆角不变。
- 不为 Windows / Android 另出设计图，也不改成 Material 风格。

桌面快捷录屏、手机系统分享（从别的 App 分享到某张单）**不进一期**；一期用本单 AI 输入框的「附件」传截图和录屏。

## 6. 暗色模式

- 只换 token，不换结构：系统色换成暗色版本；glass 换成深灰半透明；壁纸换成深蓝 / 紫 / 青柔光。
- 「对话」菜单图标从白底换成深灰底（`#3A4157 → #262B3C`），其余彩色图标不变。
- 被测页面的截图保持亮色（那是 Tita 产品本身的样子）。
- 每张设计图都要同时出亮色和暗色。

## 11. 第一次使用的步骤器（2026-11-24 精简 4 步定稿）

图：`PC-步骤器-0-连接AI`、`PC-步骤器-1-连接器与鉴权`、`PC-步骤器-1-新建连接器鉴权`、`PC-步骤器-1-工单鉴权与触发条件`、`PC-步骤器-1-向导AI帮手`、`PC-步骤器-2-授权项目与代码`、`PC-步骤器-2-挑选仓库`、`PC-步骤器-2-微调配置`、`PC-首次使用步骤器`（第 3 步测试环境）、`PC-首次使用步骤器-正式环境`、`PC-步骤器-3-添加账号`、`PC-步骤器-4-体检并开工`、`PC-步骤器-4-体检完整日志`、`移动端-首次使用步骤器`。源 `scripts/gen-onboard.py`、`scripts/onboard_steps.py`、`scripts/gen-onboard-m.py`、`scripts/gen-missing-gaps.py`。

**设计原则（AI-Native 去表单化）**：只让人做「AI 猜不出来且涉及安全红线」的决策（连接器鉴权、代码可修改/仅查看边界、环境登录账号与数据权限），分支、构建命令、基础编码规范和修单找项目一律由 AI 自动探测推测。填的和「设置 → 连接器 / 项目」是**同一份数据**，跳过向导后随时在设置里补配。

**精简 4 步**（管理员首次未接 AI 时前置第 0 步 `连接 AI`，普通成员不可见）：

1. **前置 0 · 管理员连接 AI**（图 `PC-步骤器-0-连接AI`）：只配工作空间级 AI 引擎（默认 `Pi · 多模型`）、主力/快速模型与网关/API Key，不再混入硬编码 GitLab 账号。
2. **第 1 步 · 连接器与鉴权**（图 `PC-步骤器-1-连接器与鉴权` + 抽屉 `PC-步骤器-1-新建连接器鉴权`）：
   - 自动筛出插件市场中 `code_source`（代码存储，至少 1 个：企业 GitLab / GitHub / Gitee / 本机代码目录 / 通用 Git 或 MCP）与 `ticket_source`（工单平台，可选可跳过：Jira / Tita / GitHub Issues / 通用 Webhook；不接也能直接手动建单）；发布、审批等连接器绝不混入。
   - 管理员配好「公司共用」连接器后，团队成员进入本步直接复用无需重填；点开右侧毛玻璃抽屉按插件 `authSchema` 动态渲染鉴权表单，Bot 实时校验连通性、账号身份、最小权限（确认无合入主干权限）与可见仓库数。
3. **第 2 步 · 授权项目与代码权限**（图 `PC-步骤器-2-授权项目与代码` + `PC-步骤器-2-挑选仓库` + `PC-步骤器-2-微调配置`）：
   - **绝不平铺全部连接器的数百个仓库**：主列表**只保留用户主动筛选留下的已授权仓库，并按来源连接器清晰分组**（如 `公司 GitLab · 已选 2/28`、`本机代码目录 · 已选 1/4`、`GitHub · 已选 1/14`，每组头自带 `+ 从此来源挑选 ›` 直达对应连接器 Tab）；顶部搜索框仅在已选仓库中本地筛选（匹配项目名/仓路径/连接器，与 `已选 / 可修改 / 仅查看` 胶囊 AND 组合）。
   - **「+ 从已连来源挑选仓库」右侧抽屉**：按已鉴权连接器分 Tab，抽屉内搜索框仅搜当前激活连接器的远端 API 或本机目录（300ms 防抖 + Group 分组 + 5 分钟缓存与刷新）；支持跨 Tab 暂存多选，新加入默认「仅查看」防误授权。
   - **「微调 ›」右侧 640px 抽屉**：归属项目（自动 1:1 建项目或并入已有项目支持 1 项目多仓）、主干/测试分支、包管理器、试构建命令与 MR 审核人覆盖；人工改过项标蓝「已人工覆盖」且不被重探测冲掉，支持一键「恢复 AI 推测」与「保存并试构建」。详细接口契约与开发步骤见 `docs/06-技术设计方案.md` §10.3。
4. **第 3 步 · 环境与账号（可跳过）**（图 `PC-首次使用步骤器`、`-正式环境`）：
   - 环境数量与账号数量均不限；凭证支持密码或 Cookie（Cookie 无需填账号名，Bot 登录后自动识别，过期橙框提醒）；每个账号明示数据权限（`只能查看` / `可以修改`）；测试数据由每张工单自提供，纯代码修复可先跳过。
5. **第 4 步 · AI 体检并开工**（图 `PC-步骤器-4-体检并开工`）：
   - Bot 真实跑一遍拉取、推测构建、只读隔离校验、环境试登录与收单预览；内置 Skills 与仓库规范默认生效，发布回滚、UI 主题、Token 费用检测等插件移出首次向导，按需去「插件市场」安装。
6. **移动端**（图 `移动端-首次使用步骤器`，4 屏）：步骤概览（4 步）→ 第 3 步环境与账号 → 添加账号底部弹层（Cookie + 数据权限）→ 第 4 步 AI 体检并开工。

- **Tooltip 静态图规约**：静态设计图原则上**不手画悬浮 Tooltip**以免遮挡主体；仅在规范展示板（`PC-组件库规范-2`）展示 `.cc-tooltip` 样本，实际运行时无文字 Dock 与禁用按钮须挂载 Tooltip 解释原因。

### 16.3 无障碍对比度（WCAG 2.1 AA）与 8 态交互契约

- **系统装饰色 vs 文字专用色分层（Apple HIG）**：`--blue / --green / --orange / --red / --purple / --teal` 仅用于图标、状态点、圆环与进度条；**所有彩色文字、标签、横幅、危险按钮与语义下拉统一使用 `--ink-*`**（亮色 `#005CC5 / #137333 / #9A4D00 / #B91C1C / #7E22CE / #0A6678`；暗色 `#6BB8FF / #4CE073 / #FFB340 / #FF948C / #D79BFF / #5CE1F5`），`--text-3` 亮 `.66` / 暗 `.64`，主按钮 `--btn-pri-bg` 亮 `#0066D6` / 暗 `#006EE6`，全表面对比度 ≥ **4.5:1**。
- **状态实底（白字 / 白图标的小圆点、步骤点、提问卡图标底）**：一律走 `--btn-ok-bg`（完成）、`--btn-pri-bg`（进行 / 选中）、`--btn-warn-bg`（待处理 / 需人工，`#B45309`）、`--btn-run-bg`（执行中 / 验证中，`#0A6678`）、`--btn-danger-bg`（失败）、`--btn-purple-bg`（回原平台确认等外部待办，`#7E22CE`），白字均 ≥ 5:1。**页面脚本里不要再直接写这些十六进制值**。连接器品牌色（GitLab / GitHub / Gitee）、Dock 图标底色、头像渐变属于品牌和插画用色，不受此限。
- **选中行嵌套标签高反差**：`.cc-menu-item.is-selected` 内嵌套 `.cc-tag-b`（如 `推荐`）自动切换亮白/暗深衬底（亮 6.1:1 / 暗 8.7:1），杜绝双层叠蓝看不清。
- **完整 8 态 + 键盘导航**：所有交互控件须实现 `default / hover / active / focus-visible（输入为 focus-within）/ selected / disabled / error / loading` 及 `prefers-reduced-motion: reduce`；模态抽屉/弹窗强制 Focus Trap + `Esc` 回焦原触发器（危险确认框禁止默认聚焦危险主按钮）；440px 非模态 AI 帮手设为 `aria-modal="false"`，严禁锁死主表单。

### 16.4 移动端标准组件库、双端适配与高危护栏（3 路移动端 Agent 审定，2026-11-24 锁版）

图：`reference/images/pages/移动端-组件库规范-亮色/暗色.png`（3 屏 1440×1000，源 `scripts/gen-mobile-components.py` → `v5/m-components.html`）；CSS 真相源：`tokens/theme.css`（`--m-*` 移动端标尺与 `--btn-ok-bg / --btn-danger-bg` 高对比实底）+ `tokens/components.css` §11（`.cc-m-*`，与 PC `.cc-*` 0% 命名冲突）。

1. **移动端触控热区与尺寸标尺（iOS HIG ≥ 44×44pt · Android M3 ≥ 48dp）**：
   - 统一移动端核心高度：`--m-input-h 46px`（输入 / OTP / 搜索 / 下拉）、`--m-row-h 48px`（分组列表行，禁止为塞进一屏压扁至 `38px`）、`--m-btn-h 48px`（主操作大按钮）、`--m-btn-sm-h 44px`（吸底双按钮）、`--m-seg-h 40px`（配透明热区扩展达 `44pt`）、`--m-nav-h 48px`（3 列 `1fr auto 1fr` 严格居中，彻底修复无右侧按钮时标题右偏）、开关 `46×28pt`（`--switch-on` + GPU `transform` + `44pt` 垂直热区）。
   - 相邻可点控件物理间距 `≥ 8pt`；吸底 `打回` 与 `审核通过` 按钮之间间距 `≥ 12pt`，防止拇指热区误触；移动端绝对字号底线 `11pt`（WebView 表单输入 `16px` 防 iOS 聚焦放大）。
   - 实底高对比按钮强制走 `--btn-pri-bg`（蓝 5.4:1）/ `--btn-ok-bg`（绿 5.1:1）/ `--btn-danger-bg`（红 5.7:1），**严禁裸用 `--blue / --green / --red` 做白字实底按钮**。
2. **导航互斥、Bottom Sheet、L2 高危锁与防误触护栏**：
   - **层级互斥**：一级 `≤ 5` 个动态核心 Tab 根页（AI 助手 / 工单 / 发布主流程 / 可配插件槽如回滚 / Skills，未启用扩展槽自动居中收口为 4 图标）恒定显示悬浮 Tab 栏（`z:20`，且有且仅有一个选中态）；二级详情/设置/回滚预览页恒定带左上角 `‹ 返回` 导航栏并隐藏 Tab 栏，严禁出现「既无返回又无 Tab」的死胡同页；首页大标题右上头像旁并置 `36px` 铃铛按钮（`44pt` 热区）唤起消息抽屉。
   - **L2 高危锁（`.cc-m-l2-lock` + `.cc-m-btn-locked`）**：命中高危核心路径的 L2 工单在手机端默认禁用 10 秒速过，展示红底 AA 锁卡说明触发规则，保留「打回」与「发到 PC 逐行审 Diff ›」快捷接力（项目高级设置可配允许手机逐行全部审毕后解锁双阶确认）。
   - **确认护栏**：有未测项时审核确认 Sheet 勾选框**默认不勾选**（整行 48px 热区）；发正式环境与紧急回滚（含连带变更）均须二次确认 + 显式署名个人 Apollo 账号；底部弹层（`.cc-m-sheet`，`r:30px, z:40`）避让 `34pt` Home Indicator，悬浮 Toast 走 `z:70` 盖过弹层并支持「撤销」。
3. **Flutter 双端工程契约（iOS + Android 120fps 预算）**：
   - **单套视觉、外科手术式系统适配**：iOS 走 `CupertinoPageRoute` 侧滑返回 + `BouncingScrollPhysics` + `CupertinoScrollbar`；Android 开启 `edgeToEdge` + API 33+ 预测性返回（`PopScope` 保护草稿）+ 自动识别 3 键导航栏（`bottomInset ≥ 36dp` 时 TabBar 紧凑至 `60dp`）+ 4dp 自动淡出 `RawScrollbar`。
   - **毛玻璃 GPU 性能预算**：单屏同时激活的真实 `BackdropFilter` 上限 **≤ 3 层**（仅悬浮顶栏 / 悬浮 Tab 或底栏 / Bottom Sheet 使用实时模糊，可滚 `ListView` 内卡片一律用高透色值 + 1px `--stroke` 模拟，保障 iOS 120fps 与中端 Android 60fps）；软键盘弹起时双行操作 Dock 自动折叠第 1 行审核按钮、仅保留单行本单 AI 输入框贴合键盘上沿。
   - **1:1 Flutter 组件映射**：`.cc-m-nav` → `CcAppBar`、`.cc-m-tabbar` → `CcFloatingTabBar`、`.cc-m-list/.cc-m-row` → `CcInsetGroup / CcListTile`、`.cc-m-select` → `CcMobileSelect`（拉起 `CcBottomSheet`）、`.cc-m-seg` → `CcSegmentedControl`、`.cc-m-switch` → `CcCupertinoSwitch`、`.cc-m-bar` → `CcStickyActionBar`、`.cc-m-review-card/.cc-m-l2-lock` → `CcReviewDeliveryCard / CcL2RiskLockBanner`、`.cc-m-toast` → `CcToast`。
